# Lock file for the project's runtime dependencies, i.e. the transitive
# closure of the "db" optional-dependency group declared in pyproject.toml
# ([project.optional-dependencies].db). This exists so `pip-audit` in CI
# (.github/workflows/validate.yml, "catalog" job) scans the exact set of
# third-party packages the FastAPI/SQLAlchemy layer ships with, instead of
# an environment that never installed them.
#
# Regeneration steps (run whenever pyproject.toml's [project.optional-
# dependencies].db list changes, or periodically to pick up patch releases):
#
#   python3 -m venv /tmp/catalog-lock-venv
#   /tmp/catalog-lock-venv/bin/pip install --upgrade pip
#   /tmp/catalog-lock-venv/bin/pip install -e ".[db]"
#   /tmp/catalog-lock-venv/bin/pip freeze | grep -v '^-e ' > requirements-lock.txt
#
# (The `pip freeze` output also contains an "-e git+...#subdirectory=..."
# line for the project itself when installed from a worktree/clone; that
# line is not a real pinned dependency and must be dropped, hence the
# `grep -v '^-e '` above.) Commit the regenerated file together with the
# pyproject.toml change in the same PR.
