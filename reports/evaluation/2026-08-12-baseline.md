# Global Civil API Catalog — 改善前評価（ベースライン）

評価日: 2026-08-12 / 対象コミット: `c902155`（v1.2.0 リリース後・PR #77 時点）/ 評価者: Codex（CTO代行）

## 1. プロジェクト概要

| 項目 | 内容 |
|---|---|
| 目的 | 土木・建設で使える国内外 API・公開データの共通台帳。現場判断・技術検討・研究・社内 IT 運用のデータ選定を支援 |
| 利用者 | 現場管理・監督者、技術者、研究者、企画・管理者、IT 部門（約600名組織のうち DX 部門7名で運用） |
| 提供価値 | 50 件の API/公開データ台帳、接続検証、スコアリング、地図可視化、成果物出力、編集・承認ワークフロー |
| 完成段階 | Phase A〜C 実装済み（DB・認証/RBAC・監査/承認）。Phase D/E（所有者管理・品質検証強化/通知）は設計のみ |
| 運用段階 | 本番稼働中（Linux systemd + Cloudflare Tunnel + Access、Neon PostgreSQL）。週次検証 cron は PR 生成まで自動化 |

## 2. 業務課題と提供価値

- 課題: API/公開データの存在・利用条件・接続可否が属人化し、現場と技術者が同じ情報を共有できない。
- 価値: 国・自治体・公的機関の一次情報を優先した台帳 + 自動接続検証 + 再現可能なスコアリングで、採用判断をデータ駆動化。
- 現状の実績: 登録 50 件、検証結果 30 件、本格利用候補 3 件（地理院標準地図タイル・国土数値情報 行政区域・気象庁 天気予報 JSON）。

## 4. 総合判定

**条件付き利用可（Conditional Production Use）**

すでに本番稼働しており、読取系・編集承認系・監査の根幹は動作している。ただし「監視・アラート欠如」「DB バックアップ/復旧未検証」「DB テストが CI で未実行」「週次検証 PR の滞留」「文書矛盾」が本番運用の条件付き要素。これらを解消すれば「本番利用可」へ引き上げられる。

## 5. 強み（20 件）

1. 要件定義書・詳細仕様設計書・Q4 epic 設計書が揃い、設計根拠（ADR）が明文化されている
2. 一次情報（国・自治体・公的機関）を優先するデータ方針が利用方針に明記
3. 50 件すべて必須項目充足・重複なし・最終確認日 90 日以内（validate 合格）
4. 接続検証が自動化され、SSRF 多層ガード（保存時検証＋解決時ピン留め）付き
5. スコアリングがルールベースで再現可能（score_breakdown に算定根拠を保存）
6. 5 ロール RBAC + ローカル認証（scrypt・ロックアウト）+ Entra OIDC を実装
7. 承認ワークフロー（draft→in_review→pending_approval→published）を状態機械で強制
8. append-only 監査ログ＋変更理由必須＋版スナップショット＋論理削除＋復元
9. 書込 API は Origin 検証・SameSite=Lax・Secure Cookie・CSP で保護
10. 静的 UI は API 停止時も閲覧継続（graceful degradation）
11. Web UI は標準ライブラリのみで稼働し、依存攻撃面が小さい
12. systemd ユーザーサービス 3 本 + Restart=always + ヘルスチェックで常駐
13. Cloudflare Tunnel + Access（OTP/ドメイン制限）による多層防御
14. 秘密情報が Git に無い（スキャンで実値ゼロ、.env は gitignore 済み）
15. CI で ruff・compileall・validate・pytest・pip-audit・export を実行
16. CodeRabbit レビューと GitHub Actions による週次検証を導入
17. エクスポート（Markdown/CSV/JSON）が画面からダウンロード可能
18. ライブマップで OSM/地理院タイルを実接続表示し、ハザードレイヤを重ねられる
19. 日本語主体の UI/文書で非エンジニアでも利用可能
20. state.json による進捗管理とハンドオフ記録の文化が定着
